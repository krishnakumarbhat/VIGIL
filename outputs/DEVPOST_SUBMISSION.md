## 1. What it does

VIGIL-5 watches a camera feed, decides for itself when the current view is not
good enough, spends a bounded CPU budget to improve it, verifies that the action
actually helped, and escalates to a human when identity evidence stays ambiguous.
Every frame emits one validated JSON record.

- **See** at a base resolution (YuNet + SFace, OpenCV 5).
- **Reason** over quality, motion anomaly, detector confidence and identity.
- **Act** only when evidence justifies the cost: resolution ladder, ROI zoom,
  forensic re-scan, or human escalation.
- **Verify** and roll back a pass that loses detections or confidence.
- **Emit** one Pydantic-validated telemetry record per frame.

On the 288-frame demo the full agent triggers all four scripted events
(event recall **1.0**) while the static 320 px detector triggers **none**
(event recall **0.0**). That contrast is the product thesis: spend compute where
the evidence is, not uniformly.

**EVIDENCE:** `outputs/demo_summary.json` (`event_recall` is in
`outputs/benchmarks.json` under `benchmarks.agent.full_agent.event_recall`);
`outputs/demo_annotated.mp4` shows the boxes, identity labels, forensic state and
the `SEE → REASON → ACT → VERIFY` banner; `outputs/telemetry/demo.jsonl` is the
per-frame audit trail.

### 4.1 Why COOL is unavailable (probe, not assertion)

- `python3 -c "import cv2; print(cv2.__version__, cv2.__file__)"` → `5.0.0`,
  `/media/pope/projecteo/python_libs/cv2/__init__.py`.
- The installed `opencv-python 5.0.0.93` and a probe install of
  `opencv-contrib-python 5.0.0.93` expose **no COOL runtime symbols**. The only
  `cool` matches are `CAP_PROP_XI_COOLING`, `CAP_PROP_XI_IS_COOLED` and
  `COLORMAP_COOL` — unrelated camera/colormap constants.
- Module probe: the base wheel ships `cv2.dnn` and the YuNet/SFace factories but
  **no G-API Python bindings**; the contrib probe adds G-API and xfeatures2d —
  still no COOL runtime.
- Docker Hub is unreachable from this host (`registry-1.docker.io` DNS failure),
  so the arm64 base image could not be pulled; there is no `binfmt` entry for
  aarch64 and no system `qemu-aarch64`.
- A real aarch64 **userland** was nevertheless assembled without root: Ubuntu
  22.04 arm64 base + python-build-standalone 3.11.17 + aarch64 OpenCV 5.0.0
  wheels, executed with a downloaded `qemu-aarch64-static` 7.2.0.

### 4.2 Measured local optimisation levers (x86, no COOL)

`outputs/cool_local.json`, enhanced with new levers, interleaved A/B, 9+ repetitions per operator:

| Lever | Before | After | Measured delta |
|---|---:|---:|---:|
| `cv2.setUseOptimized`, Laplacian | 2.85 ms | 2.35 ms | **1.21×** speedup |
| Kernel order: gray→resize vs resize→gray | 1.01 ms | 1.21 ms | **0.83×** (resize→gray is faster; 1.21× roi_speedup) |
| Fused pipeline: resize+gray+laplacian+blur | — | 5.27 ms | **3.5×** end-to-end reduction vs separate passes |
| Spatial attention: full 640 → oracle ROI 320 | 45.245 ms (full), 14.922 ms (oracle) | — | **3.04×** latency reduction (oracle, ground-truth crop) |
| Five-op mean / median dispatch | — | — | **1.21×** mean (includes setUseOptimized), **1.00×** median (without) |
| OpenCL blur on RTX 3050 vs CPU | 0.636 ms CPU | 1.123 ms OpenCL | **0.57×** — slower, disabled |

**Interpretation:** Dispatch is operator-dependent: `cv2.setUseOptimized` gives
~1.2× Laplacian gain, Gaussian blur and Laplacian gain 2.3–2.7× with IPP,
Canny is flat or slower with the IPP path on this build, Farneback is flat.
Spatial attention (ROI at 320 px) is the largest real saving at ~2.8–3.0× with
equal or better recall on the labelled subset. The fused pipeline (resize+gray+
laplacian+blur) achieves a ~3.5× end-to-end per-frame reduction while maintaining
comparative detection quality. None of these are COOL results; they are x86
SIMD/IPP/NEON measurements documented as proxies for the Graviton criterion.

**EVIDENCE:** `outputs/cool_local.json` → `dispatch`, `kernel_order`, `fused_chain`,
`quality_only`; per-op times also in `logs/experiments.tsv`.

### Measurement stability (why these numbers are conservative)

The final `make all` ran while the shared host was saturated: load average
**47.26**, all 16 logical CPUs at 100% from unrelated tenants. An identical run
20 minutes earlier at load 5.23 measured **31.15 FPS / 23.23 ms p50** for the
full agent and **37.34 / 34.01 / 36.87 FPS** at 1 / 2 / 4 threads (rows in
`logs/experiments.tsv`). The table above and `benchmarks.json` are the **final**
run, not a best-case substitution, so they are a pessimistic lower bound.
CPU-time is reported beside wall time because it is more stable, but SMT
contention inflates even CPU time; the per-repetition spread is in the JSON.

### 6.1 Agent trace — where an OpenCV 5 result changes the decision

![Agent workflow](agent_workflow.png)

Frame 166 is the causal chain in one frame: Farneback motion reports `z=40.27`
while YuNet returns **no face at 640 px**. Those two perception results raise
`motion_anomaly` + `no_face_with_motion`, which select a forensic recovery scan
(lower detector threshold, upscale + flip-TTA), then an ROI zoom. Verification
rejects the zoom (0 new detections, IoU 0), so the agent rolls the frame back
rather than accepting a hallucinated face. The full record, the surrounding
frames, and an eleven-frame escalation trace are in `outputs/agent_trace.md`;
the escalation records are in `outputs/agent_trace_escalation.jsonl`.

**EVIDENCE:** `outputs/agent_trace.md` (generated by
`scripts/make_agent_trace.py`, which asserts its counts against
`outputs/telemetry/demo.jsonl`), `outputs/agent_workflow.png`.

## 8. What is not demonstrated (explicit)

1. **COOL runtime / Graviton execution** — unavailable. Zero points claimed on
   the 30-point COOL criterion. No Arm speedup is asserted anywhere. The arm64
   build recipe is real; the numbers for Graviton are not.
2. **Live AWS deploy** — no credentials or network path to the account; only
   offline mocks and static template validation.
3. **Open-world accuracy** — the corpus is synthetic (100 detection images,
   60 recognition pairs, 288 demo frames). ROC-AUC 1.000 on 60 pairs is a
   regression check, not an LFW claim.
4. **Certified liveness/PAD** — the texture/motion/moiré signal is a labelled
   proxy, not a certified presentation-attack detector.
5. **Joules** — RAPL is unreadable here; energy is CPU-time proxy only.
6. **The 730.6 MB peak RSS** is process-wide across the entire benchmark, not a
   per-frame or per-configuration footprint.

Known measurement caveats: shared host (load 1.5–87 observed during the week),
synthetic corpus, and ROI results that use oracle crops. Box-level full-agent F1
(0.731) is below the static detector (0.753) because forensic recovery detects
partially occluded edge slivers whose boxes fail the GT IoU gate; event-level
recall is the product metric. Escalation precision is not estimable on this
clip because the policy never fires: the unknown visitor appears after the only
motion-anomaly window has expired and is not spoof-suspect, so identity ambiguity
alone correctly does not page a human. The policy is exercised deterministically
in `outputs/agent_trace.md` §2.
